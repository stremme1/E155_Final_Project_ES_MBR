# FPGA Setup and Deployment Guide

Complete step-by-step guide for setting up and deploying the drum system on iCE40 FPGA.

## Prerequisites

1. **Lattice Diamond or Radiant Software** (for iCE40)
   - Download from: https://www.latticesemi.com/en/Products/DesignSoftwareAndIP/FPGAandLDS/LatticeDiamond
   - Or use Radiant (newer tool): https://www.latticesemi.com/en/Products/DesignSoftwareAndIP/FPGAandLDS/LatticeRadiant

2. **iCE40 FPGA Development Board**
   - iCE40 UltraPlus recommended (iCE40UP3K or iCE40UP5K)
   - **For UP5K users**: See `UP5K_SETUP.md` for device-specific guidance
   - Ensure board has I2C pins available

3. **Hardware Components**
   - 2x BNO055 IMU sensors
   - Pull-up resistors (10kΩ) on I2C lines (if not on board)
   - Buttons for kick drum and calibration
   - LEDs for status indication

## Step 1: Generate I2C IP Using Module Generator

### 1.1 Launch Module Generator

1. Open Lattice Diamond/Radiant
2. Create a new project for your iCE40 device
3. Navigate to **Tools → Module Generator** (or **IP → Module Generator**)

### 1.2 Configure I2C1 (Left I2C - IMU 1)

1. **Enable Left I2C**:
   - Check "Enable Left I2C" option
   - This enables I2C1 for the first BNO055 sensor

2. **I2C Configuration Tab**:
   - **Mode**: Master
   - **I2C Clock Rate (Desired)**: 400 kHz (BNO055 supports up to 400kHz)
   - **System Clock**: 48 MHz (if using SB_HFOSC) or your system clock frequency
   - **I2C Clock Rate (Actual)**: Verify it's close to 400kHz
   - **Addressing**: 7-bit addressing
   - **General Call Enable**: Disabled (unless needed)
   - **Wakeup Enable**: Disabled (unless needed)
   - **Interrupts**: Enable "TX/RX Ready" interrupts
   - **Include I/O Buffers**: ✅ **ENABLED** (Important!)

3. **General Tab**:
   - **System Clock**: 48 MHz (or your clock frequency)
   - **Configuration Clock Source**: SB_HFOSC (for iCE40 Ultra/UltraPlus)

### 1.3 Configure I2C2 (Right I2C - IMU 2)

1. **Enable Right I2C**:
   - Check "Enable Right I2C" option
   - This enables I2C2 for the second BNO055 sensor

2. **I2C Configuration Tab**:
   - Same settings as I2C1
   - **Mode**: Master
   - **I2C Clock Rate**: 400 kHz
   - **Interrupts**: Enable "TX/RX Ready"
   - **Include I/O Buffers**: ✅ **ENABLED**

### 1.4 Generate IP

1. Click **Generate** or **OK**
2. Save the generated files to your project directory
3. Note the generated module name (typically `i2c_master_top` or similar)

### 1.5 Review Generated Files

The Module Generator creates:
- **Soft IP wrapper** (e.g., `i2c_master_top.v` or `.sv`)
- **System Bus interface** with IPLOAD/IPDONE signals
- **I2C physical pins** (handled internally)

**Important**: The generated wrapper has:
- `IPLOAD` input - Assert to start IP configuration
- `IPDONE` output - Goes high when IP is ready
- System Bus interface (SBCLKi, SBWRi, SBSTBi, etc.)
- I2C physical pins (SCL/SDA) - **These are handled internally**

## Step 2: Integrate Generated IP with Your Design

### 2.1 Instantiate I2C IP Wrappers

Create a wrapper file or add to your top-level module:

```systemverilog
// Instantiate I2C1 Soft IP wrapper (generated by Module Generator)
i2c_master_top i2c1_wrapper (
    // Clock and Reset
    .SBCLKi(i2c1_sb_clk),
    .SBWRi(i2c1_sb_wr),
    .SBSTBi(i2c1_sb_stb),
    .SBADRi(i2c1_sb_addr),
    .SBDATi(i2c1_sb_data_i),
    .SBDATo(i2c1_sb_data_o),
    .SBACKo(i2c1_sb_ack),
    .I2CPIRQ(i2c1_irq),
    
    // IP Configuration
    .IPLOAD(i2c1_ipload),
    .IPDONE(i2c1_ipdone),
    
    // I2C Physical Pins (handled internally by wrapper)
    .I2C1_SCL(),  // Connected internally
    .I2C1_SDA()   // Connected internally
);

// Instantiate I2C2 Soft IP wrapper
i2c_master_top i2c2_wrapper (
    // Same interface as I2C1
    .SBCLKi(i2c2_sb_clk),
    .SBWRi(i2c2_sb_wr),
    .SBSTBi(i2c2_sb_stb),
    .SBADRi(i2c2_sb_addr),
    .SBDATi(i2c2_sb_data_i),
    .SBDATo(i2c2_sb_data_o),
    .SBACKo(i2c2_sb_ack),
    .I2CPIRQ(i2c2_irq),
    
    .IPLOAD(i2c2_ipload),
    .IPDONE(i2c2_ipdone),
    
    .I2C2_SCL(),  // Connected internally
    .I2C2_SDA()   // Connected internally
);
```

### 2.2 Verify System Bus Register Addresses

**CRITICAL**: The generated IP may use different register addresses than assumed in `bno055_i2c_controller.sv`.

1. **Check the generated wrapper file** for register addresses:
   ```systemverilog
   // Typical addresses (verify in your generated file):
   // 0x00: Control Register
   // 0x01: Transmit Data Register
   // 0x02: Receive Data Register
   // 0x03: Status Register
   ```

2. **Update `bno055_i2c_controller.sv`** if addresses differ:
   ```systemverilog
   // Update these if your generated IP uses different addresses
   localparam I2C_CTRL_REG = 8'h00;  // Verify in generated IP
   localparam I2C_TX_REG = 8'h01;     // Verify in generated IP
   localparam I2C_RX_REG = 8'h02;     // Verify in generated IP
   localparam I2C_STATUS_REG = 8'h03; // Verify in generated IP
   ```

3. **Refer to Advanced iCE40 I2C Usage Guide** (FPGA-TN-02011) for exact register map

### 2.3 Connect to Your Top Module

Your `drum_system_top.sv` already has the correct interface. Just ensure:

1. **System Bus clocks are assigned**:
   ```systemverilog
   assign i2c1_sb_clk = clk;
   assign i2c2_sb_clk = clk;
   ```

2. **IPLOAD/IPDONE are connected** (already done in your code)

3. **System Bus signals connect to I2C wrappers** (already done)

## Step 3: Pin Assignment

**See `PIN_ASSIGNMENT.md` for complete pin assignment details.**

### 3.1 I2C Physical Pins - **DIFFERENT PINS**

**CRITICAL**: I2C1 and I2C2 use **DIFFERENT physical pins** - they are separate I2C controllers.

The Module Generator assigns I2C pins automatically:

**I2C1 (Left I2C - IMU 1 / Right Hand)**:
- **I2C1_SCL**: Left I2C dedicated clock pin (upper left corner)
- **I2C1_SDA**: Left I2C dedicated data pin (upper left corner)
- **Location**: Upper left corner of iCE40 chip

**I2C2 (Right I2C - IMU 2 / Left Hand)**:
- **I2C2_SCL**: Right I2C dedicated clock pin (upper right corner)
- **I2C2_SDA**: Right I2C dedicated data pin (upper right corner)
- **Location**: Upper right corner of iCE40 chip

**Important**: 
- I2C pins are **open-drain** - pull-up resistors are required
- **On-board 10kΩ pull-ups**: If your board has them, these are **perfect** for 400kHz I2C
- **External 10kΩ pull-ups**: Use if on-board pull-ups are not available
- Internal pull-ups (50kΩ-100kΩ) are too weak for 400kHz I2C - **not recommended**
- **See `I2C_PULLUP_GUIDE.md`** for detailed pull-up information
- **Verify on-board pull-ups**: Check your board schematic to confirm
- I2C1 and I2C2 are **completely independent** - different physical pins

### 3.2 User Interface Pins - **DIFFERENT PINS**

Each signal needs its own GPIO pin. Assign in Pin Assignment Editor:

```
button1       -> GPIO pin (with pull-up) - e.g., PIN_15
button2       -> GPIO pin (with pull-up) - e.g., PIN_16
led1          -> GPIO pin                - e.g., PIN_17
led2          -> GPIO pin                - e.g., PIN_18
sound_id[0]   -> GPIO pin                - e.g., PIN_19
sound_id[1]   -> GPIO pin                - e.g., PIN_20
sound_id[2]   -> GPIO pin                - e.g., PIN_21
sound_id[3]   -> GPIO pin                - e.g., PIN_22
sound_id[4]   -> GPIO pin                - e.g., PIN_23
sound_id[5]   -> GPIO pin                - e.g., PIN_24
sound_id[6]   -> GPIO pin                - e.g., PIN_25
sound_id[7]   -> GPIO pin                - e.g., PIN_26
rst_n         -> GPIO pin or dedicated reset pin
```

**Note**: Replace pin numbers with actual pins from your device pinout.

### 3.3 Clock Pin

**If using SB_HFOSC (recommended)**:
- No pin assignment needed - clock is internal
- `clk_ext` is only used for simulation

**If using external clock**:
```
clk_ext -> Dedicated clock input pin (GBUF, e.g., G0-G7)
```

## Step 4: Synthesis and Implementation

### 4.1 Add Source Files

In Lattice Diamond/Radiant:

1. **Add SystemVerilog files**:
   - `drum_system_top.sv`
   - `bno055_i2c_controller.sv`
   - `system_bus_master.sv`
   - `quaternion_to_euler.sv`
   - `gesture_recognition.sv`

2. **Add generated I2C IP files**:
   - Generated wrapper file (e.g., `i2c_master_top.v`)

3. **Set top-level module**: `drum_system_top`

### 4.2 Synthesis Settings

1. **Synthesis Tool**: Lattice LSE or Synplify Pro
2. **Language**: SystemVerilog
3. **Optimization**: Speed or Area (as needed)

### 4.3 Implementation

1. **Run Synthesis** (F5 or Process → Run Synthesis)
2. **Run Place & Route** (F6 or Process → Run Place & Route)
3. **Check for errors/warnings**

### 4.4 Timing Analysis

1. **Run Timing Analysis** to verify:
   - Setup/hold times are met
   - Clock domain crossings are handled
   - System Bus timing is correct

2. **Review timing report** for any violations

## Step 5: Hardware Connections

### 5.1 I2C Connections

**BNO055 Sensor 1 (Right Hand)**:
```
BNO055 VIN  -> 3.3V
BNO055 GND  -> GND
BNO055 SCL  -> I2C1_SCL (with 10kΩ pull-up to 3.3V)
BNO055 SDA  -> I2C1_SDA (with 10kΩ pull-up to 3.3V)
BNO055 ADR  -> GND (for address 0x28) or 3.3V (for address 0x29)
```

**BNO055 Sensor 2 (Left Hand)**:
```
BNO055 VIN  -> 3.3V
BNO055 GND  -> GND
BNO055 SCL  -> I2C2_SCL (with 10kΩ pull-up to 3.3V)
BNO055 SDA  -> I2C2_SDA (with 10kΩ pull-up to 3.3V)
BNO055 ADR  -> GND (for address 0x28) or 3.3V (for address 0x29)
```

**Note**: If both sensors use address 0x28, connect one ADR to GND and one to 3.3V

### 5.2 User Interface Connections

```
Button 1 (Kick) -> button1 pin (with pull-up)
Button 2 (Cal)  -> button2 pin (with pull-up)
LED 1           -> led1 pin
LED 2           -> led2 pin
```

### 5.3 Power

```
FPGA VCC       -> 3.3V (or as per board requirements)
FPGA GND       -> GND
BNO055 VIN     -> 3.3V
BNO055 GND     -> GND (common with FPGA GND)
```

## Step 6: Programming the FPGA

### 6.1 Generate Bitstream

1. **Run Bitstream Generation** (F7 or Process → Generate Bitstream)
2. **Output file**: `.jed` file for iCE40

### 6.2 Program FPGA

**Option A: Using Lattice Programmer**:
1. Connect programmer (Lattice Programmer or compatible)
2. Open Lattice Programmer
3. Load `.jed` file
4. Program device

**Option B: Using SPI Flash**:
1. Generate SPI Flash image
2. Program flash memory
3. FPGA will configure from flash on power-up

**Option C: Using On-Board Programmer**:
- Follow your development board's programming instructions

## Step 7: Verification and Testing

### 7.1 Initial Power-Up

1. **Power on the system**
2. **Observe LEDs**:
   - Should indicate system status
   - May blink during initialization

3. **Check I2C Communication**:
   - Use I2C analyzer or oscilloscope
   - Verify I2C transactions on SCL/SDA lines

### 7.2 Functional Testing

1. **Button Test**:
   - Press Button 1 (kick) - should trigger sound
   - Press Button 2 (calibration) - should calibrate

2. **Gesture Test**:
   - Move sensors to trigger gestures
   - Verify sound_id output changes

3. **Calibration Test**:
   - Press calibration button
   - Hold sensors still for calibration
   - Verify system responds correctly

### 7.3 Debugging

**If I2C communication fails**:
1. Check pull-up resistors (10kΩ on SCL and SDA)
2. Verify I2C addresses (0x28 or 0x29)
3. Check System Bus register addresses match generated IP
4. Verify IPLOAD/IPDONE sequence completes
5. Use oscilloscope to check I2C signals

**If system doesn't initialize**:
1. Check reset signal (should be high for normal operation)
2. Verify clock is running (check with oscilloscope)
3. Check IPDONE signals go high after IPLOAD

**If gestures don't work**:
1. Verify quaternion data is being read
2. Check Euler angle calculations
3. Verify gesture recognition logic
4. Check calibration offsets

## Step 8: Optimization (Optional)

### 8.1 Clock Frequency

- Adjust SB_HFOSC divider if needed
- Verify I2C clock rate is correct
- Balance between speed and power consumption

### 8.2 Resource Usage

- Review synthesis report for resource usage
- Optimize if approaching device limits
- Consider using smaller data widths if needed

### 8.3 Power Consumption

- Use clock gating for unused modules
- Optimize state machines for power efficiency
- Consider sleep modes if available

## Troubleshooting

### Common Issues

1. **I2C IP doesn't initialize**:
   - Verify IPLOAD is asserted
   - Wait for IPDONE before using I2C
   - Check System Bus clock is running

2. **System Bus protocol violations**:
   - Verify STB/ACK timing
   - Check address/data stability
   - Review System Bus master implementation

3. **BNO055 not responding**:
   - Check I2C address (0x28 vs 0x29)
   - Verify pull-up resistors
   - Check I2C clock rate (should be ≤ 400kHz)
   - Verify BNO055 is powered and initialized

4. **Timing violations**:
   - Review timing analysis report
   - Add pipeline stages if needed
   - Adjust clock frequency if necessary
