# Critical Implementation Notes for iCE40 I2C IP

Based on the iCE40 I2C and SPI Hardened IP User Guide (FPGA-TN-02010-1.8), the following are critical requirements:

## Module Generator Soft IP Wrapper

**IMPORTANT**: The Module Generator creates a **Soft IP wrapper** around the Hard IP. You must:

1. **Generate I2C IP using Module Generator** - This creates the Soft IP wrapper
2. **Connect to the Soft IP wrapper**, not directly to Hard IP
3. **Handle IPLOAD and IPDONE signals** from the Soft IP wrapper

### IPLOAD and IPDONE Protocol

According to Section 10.1 of the datasheet:
- **IPDONE = 1** when Hard IP Configuration is complete
- **IPDONE = 0** during configuration
- **Set IPLOAD = 1** and then **wait for IPDONE = 1** before the IP can be fully utilized

**Implementation**:
```systemverilog
// Initialize I2C IP
ipload <= 1;
// Wait for IPDONE
while (!ipdone) begin
    // Wait
end
// Now I2C IP is ready to use
```

## System Bus Interface Signals

According to Table 4.1, the System Bus interface has these signals:

| Signal | Direction | Description |
|--------|-----------|-------------|
| SBCLKi | I | System clock input |
| SBWRi | I | System Read/Write input. R=0, W=1 |
| SBSTBi | I | System Strobe Signal |
| SBADRi[7:0] | I | System Bus Control Registers Address |
| SBDATi[7:0] | I | System Data Input |
| SBDATo[7:0] | O | System Data Output |
| SBACKo | O | System Acknowledgement |
| I2CPIRQ | O | Interrupt request output |

### System Bus Protocol

1. **Address and data must be stable** when SBSTBi is asserted
2. **Wait for SBACKo** before completing the transaction
3. **SBSTBi** should remain asserted until SBACKo is received

## I2C Register Map

The I2C IP has its own register map accessed via System Bus. These are **NOT** the BNO055 register addresses.

You need to:
1. Write to I2C control registers to configure I2C transactions
2. Write slave address and register address to I2C transmit register
3. Read data from I2C receive register

**Note**: The exact register addresses depend on the I2C IP implementation. You'll need to refer to:
- Advanced iCE40 I2C and SPI Hardened IP Usage Guide (FPGA-TN-02011) for register map details
- The generated Soft IP wrapper code from Module Generator

## Module Generator Configuration

When using Module Generator:

1. **Enable Left I2C** (I2C1) for IMU 1
2. **Enable Right I2C** (I2C2) for IMU 2
3. **Configure as Master mode**
4. **Set I2C clock rate**: 100kHz or 400kHz (BNO055 supports up to 400kHz)
5. **System Clock**: Set to your system clock frequency
6. **Enable interrupts**: TX/RX Ready interrupts recommended

## Physical I2C Pins

**IMPORTANT**: The I2C physical pins (I2Cx_SCL, I2Cx_SDA) are handled by the Soft IP wrapper generated by Module Generator. 

- **Do NOT** expose these as `inout` in your top-level module
- The Module Generator wrapper handles the I2C pins internally
- Only the System Bus interface needs to be connected

## Implementation Details

### Completed Features

1. **BNO055 Initialization Sequence** ✅
   - Soft reset: Writes 0x20 to register 0x3F
   - 650ms delay after reset
   - Set operation mode: Writes 0x0C (NDOF) to register 0x3D
   - 30ms delay after mode change
   - Initialization complete flag tracks status

2. **I2C Transaction Sequences** ✅
   - Complete state machine for reading all quaternion registers (W, X, Y, Z - LSB and MSB)
   - Complete state machine for reading all gyroscope registers (X, Y, Z - LSB and MSB)
   - Continuous reading loop after initialization
   - Proper System Bus protocol implementation

3. **Data Processing** ✅
   - Combines LSB and MSB bytes into 16-bit values
   - Proper sign extension for gyroscope data (signed 16-bit)
   - Data valid signal assertion when complete dataset is ready

### Implementation Notes

**I2C Register Map Assumptions:**
The implementation uses typical I2C IP register addresses:
- `0x00`: Control Register (start/stop I2C)
- `0x01`: Transmit Data Register
- `0x02`: Receive Data Register  
- `0x03`: Status Register

**Note**: When using Module Generator, verify these addresses match the generated Soft IP wrapper. Adjust if necessary.

**I2C Transaction Flow:**
1. Write to Control Register to start I2C transaction
2. Write slave address + register address to TX Register
3. Read data from RX Register
4. Repeat for multi-byte reads

**Current Limitations:**
- Simplified I2C transaction flow (assumes I2C IP handles start/stop/repeated start internally)
- Error handling not yet implemented (NACK detection, timeout)
- Register address selection not yet implemented (reads from fixed sequence)
