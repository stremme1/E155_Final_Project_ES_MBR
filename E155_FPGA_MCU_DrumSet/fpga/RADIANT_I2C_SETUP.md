# Adding I2C IP Blocks in Lattice Radiant - Step-by-Step Guide

## Overview

This guide shows you how to add the I2C Hard IP blocks to your project in Lattice Radiant. The iCE40UP5K has two hardened I2C IP blocks that you'll configure using the Module Generator.

## Prerequisites

1. **Lattice Radiant** installed (download from Lattice website)
2. **iCE40UP5K** project created in Radiant
3. Your SystemVerilog files ready (`drum_system_top.sv`, etc.)

## Step 1: Open Module Generator

1. In Lattice Radiant, open your project
2. Go to **Tools → Module Generator** (or **IP → Module Generator**)
   - Alternative: Right-click in Project Navigator → **New → IP → Module Generator**

## Step 2: Configure General Settings

1. In the Module Generator window, select the **General** tab
2. Configure:
   - **Device**: iCE40UP5K
   - **System Clock**: **48 MHz** (for HFOSC/HSOC)
   - **Configuration Clock Source**: **HFOSC/HSOC** (or **SB_HFOSC**)
   - ✅ **Enable Left I2C** (I2C1)
   - ✅ **Enable Right I2C** (I2C2)

## Step 3: Configure I2C1 (Left I2C - IMU 1)

1. Click on the **I2C** tab (or **Left I2C** tab if separate)
2. For **I2C1 (Left I2C)**:
   - **Mode**: **Master**
   - **I2C Clock Rate (Desired)**: **400 kHz**
   - **System Clock**: **48 MHz**
   - **I2C Clock Rate (Actual)**: Verify it shows ~400 kHz
   - **Addressing**: **7-bit**
   - **Interrupts**: ✅ Enable **TX/RX Ready**
   - **Include I/O Buffers**: ✅ **ENABLED** (Important!)

**Note**: Other interrupt options (General Call, Wake Up, Arbitration Lost, Overrun/NACK) can be left disabled for BNO055 communication.

## Step 4: Configure I2C2 (Right I2C - IMU 2)

1. Still in the **I2C** tab, configure **I2C2 (Right I2C)**:
   - **Mode**: **Master**
   - **I2C Clock Rate (Desired)**: **400 kHz**
   - **System Clock**: **48 MHz**
   - **I2C Clock Rate (Actual)**: Verify it shows ~400 kHz
   - **Addressing**: **7-bit**
   - **Interrupts**: ✅ Enable **TX/RX Ready**
   - **Include I/O Buffers**: ✅ **ENABLED** (Important!)

## Step 5: Generate IP

1. Click **Generate** (or **OK**)
2. Choose where to save the generated files:
   - Recommended: Save in your project directory (e.g., `ip/` or `generated/`)
3. Note the generated module name (typically `i2c_master_top` or similar)

## Step 6: Review Generated Files

The Module Generator creates:

1. **Soft IP Wrapper** (e.g., `i2c_master_top.v` or `.sv`)
   - This is the module you'll instantiate in your top-level design
   - Contains System Bus interface
   - Handles IPLOAD/IPDONE signals
   - Manages I2C physical pins internally

2. **Configuration files** (if any)

## Step 7: Add Generated Files to Project

1. In Radiant Project Navigator:
   - Right-click on your project → **Add Source Files**
   - Navigate to where you saved the generated IP files
   - Select the generated wrapper file (e.g., `i2c_master_top.v`)
   - Click **Add**

2. Verify the file appears in your project

## Step 8: Instantiate I2C IP in Your Top Module

You need to instantiate the generated I2C wrapper in your `drum_system_top.sv`. 

**IMPORTANT**: Your current `drum_system_top.sv` has System Bus ports but doesn't instantiate the I2C IP wrappers. You need to add the instantiations.

### Option 1: Add I2C Physical Pins to Top Module

If the generated IP exposes I2C physical pins, add them to your top module:

```systemverilog
module drum_system_top (
    // ... existing ports ...
    
    // I2C Physical Pins (add these if generated IP exposes them)
    inout  logic        i2c1_scl,  // I2C1 SCL (physical pin)
    inout  logic        i2c1_sda,  // I2C1 SDA (physical pin)
    inout  logic        i2c2_scl,  // I2C2 SCL (physical pin)
    inout  logic        i2c2_sda   // I2C2 SDA (physical pin)
);
```

### Option 2: Instantiate I2C IP Wrappers

Add these instantiations inside your `drum_system_top` module:

```systemverilog
// Instantiate I2C1 Soft IP wrapper (generated by Module Generator)
// NOTE: Replace "i2c_master_top" with actual module name from generated IP
i2c_master_top i2c1_ip (
    // System Bus Clock
    .SBCLKi(i2c1_sb_clk),
    
    // System Bus Interface
    .SBWRi(i2c1_sb_wr),
    .SBSTBi(i2c1_sb_stb),
    .SBADRi(i2c1_sb_addr),
    .SBDATi(i2c1_sb_data_i),
    .SBDATo(i2c1_sb_data_o),
    .SBACKo(i2c1_sb_ack),
    .I2CPIRQ(i2c1_irq),
    
    // IP Configuration
    .IPLOAD(i2c1_ipload),
    .IPDONE(i2c1_ipdone),
    
    // I2C Physical Pins (if exposed by generated IP)
    .I2C1_SCL(i2c1_scl),  // Check generated IP for exact port name
    .I2C1_SDA(i2c1_sda)   // Check generated IP for exact port name
);

// Instantiate I2C2 Soft IP wrapper
i2c_master_top i2c2_ip (
    .SBCLKi(i2c2_sb_clk),
    .SBWRi(i2c2_sb_wr),
    .SBSTBi(i2c2_sb_stb),
    .SBADRi(i2c2_sb_addr),
    .SBDATi(i2c2_sb_data_i),
    .SBDATo(i2c2_sb_data_o),
    .SBACKo(i2c2_sb_ack),
    .I2CPIRQ(i2c2_irq),
    .IPLOAD(i2c2_ipload),
    .IPDONE(i2c2_ipdone),
    .I2C2_SCL(i2c2_scl),
    .I2C2_SDA(i2c2_sda)
);
```

**CRITICAL**: 
- Check your generated IP file for the **exact module name** (may not be `i2c_master_top`)
- Check for **exact port names** (may differ from examples)
- Some generated IPs may handle I2C pins internally (no ports needed)

## Step 9: Pin Assignment

1. In Radiant, go to **Tools → Pin Assignment Editor**
2. The I2C physical pins (SCL/SDA) are **automatically assigned** by the Module Generator to dedicated I2C pins
3. For other signals (buttons, LEDs, sound_id), assign manually:
   - Select your top-level module
   - Assign pins for:
     - `button1`, `button2`
     - `led1`, `led2`
     - `sound_id[7:0]`
     - `clk_ext` (if using external clock)
     - `rst_n`

## Step 10: Verify I2C Pin Locations

The Module Generator assigns I2C pins automatically:

- **I2C1 (Left I2C)**: Upper left corner dedicated I2C pins
- **I2C2 (Right I2C)**: Upper right corner dedicated I2C pins

You can verify in Pin Assignment Editor - these should be pre-assigned.

## Common Issues and Solutions

### Issue: Module Generator not showing I2C options
**Solution**: 
- Ensure you selected iCE40UP5K device
- Check that you're using a version of Radiant that supports iCE40UP5K

### Issue: Generated module name doesn't match
**Solution**: 
- Check the actual generated file name
- Update your instantiation to match the generated module name

### Issue: I2C pins not showing in Pin Assignment
**Solution**: 
- I2C pins are handled internally by the wrapper
- You only need to assign user interface pins (buttons, LEDs, etc.)

### Issue: IPLOAD/IPDONE signals not found
**Solution**: 
- These are generated by Module Generator
- Check the generated wrapper file for exact signal names
- They may be named differently (e.g., `IPLOAD`, `IPDONE` vs `ipload`, `ipdone`)
